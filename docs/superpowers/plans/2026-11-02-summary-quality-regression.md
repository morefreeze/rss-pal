# Summary quality regression and generation provenance

Approved scope: reusable evidence-based evaluations, one shared faithfulness policy across every summary generation route, and persisted version/model/input provenance. Run real-model regressions and update the existing private QA checklist. Do not bulk regenerate historical summaries and do not add a production second-model reviewer.

## Delivery and ownership

1. Freeze fixtures and build an offline evaluation runner (independent evaluation task): `backend/internal/summaryeval/`, `backend/cmd/summary-eval/`, `backend/internal/summaryeval/testdata/`, `docs/operations/summary-quality-evaluation.md`. Evidence-backed cases for attribution/metric/time (017), nested workflow termination (018), mathematical domain/exclusion (019), plus independently worded held-out variants and positive/negative grading controls. Semantic rubrics, paraphrases accepted; no exact-output matching. Fixture/schema/grader tests must first fail. Runner must have bounded opt-in model calls, save outputs and provider completion evidence, and never touch article rows or write credentials. Source excerpts are fixture inputs, explicitly distinguished from full articles. Root runs and independently assesses actual model outputs.
2. Shared generation policy: `backend/internal/ai/summary_quality.go`, `summarizer.go`, `local_summary.go` and tests. Give factual rules a stable version, strengthen general rules for the three defect classes, apply to default/custom/text/stream/vision/browser generation; retain existing custom-template semantics and adaptive default lengths. All generated results carry actual per-stage model and effective template/prompt/input fingerprints, including vision fallbacks. Local models are explicitly client-reported, never server-verified.
3. Durable provenance: new nullable JSONB migration; model and repository summary completion methods. Save metadata with the same CAS/lease-protected write as results. Old summaries stay unknown, without backfill or false current-version labels. Invalidation and legacy writes must not retain stale provenance. Read it on article detail. Audit copying/imports and all worker/manual entry points.
4. Local/browser integration and server wiring: `backend/internal/service/summarizer.go`, `backend/internal/api/article.go`, `local_summary.go`, worker paths, `frontend/src/api/client.ts` and tests. Preserve existing `summary_version` output-CAS semantics. Bind local prompt provenance to current content/title/template/policy, reject stale inputs, accept only bounded model identifiers and no credentials/provider configuration. Test saving, invalidation, supersession and error paths.
5. Review and verification: separate specification and code-quality reviews, Go suite and frontend relevant tests/build, optional PostgreSQL integration where supported. Real-model regression uses configured production model, frozen fixtures + held-outs, records semantic findings and completion evidence; no fabricated pass from prompt-string tests. Report sample and generic regression acceptance separately.
6. Integrate latest `origin/master`, push actual master, deploy established Tencent target, verify deployed SHA, health, schema and end-user generation/provenance behavior. Preserve unrelated canonical-worktree modifications. Update existing private Page and local TODO/state/index with evidence and exact counts; leave historical summary issues open if their stored outputs have not been revalidated.

## Verification boundaries

- Generation transport/unit tests prove route coverage and request/result wiring, not semantic accuracy.
- Real-model semantic verdicts cite source and output; incomplete model output is a failure, not a passing truncated sample.
- Content hashes identify the persisted input; prompt hashes identify the effective prompts, including template text and brief supplied to detailed generation. Image metadata identifies selected image content when applicable.
- Existing archived and shared snapshots retain their historical status. No bulk update, enqueue or regenerate operation is part of this delivery.
- Source/policy/template/model lineage identifies what generated a summary; it is not a quality certification.
