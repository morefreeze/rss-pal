# Shortcut capture notes implementation plan

**Goal:** Every iPhone share can record why the link matters, preserving that private note through pending confirmation and eventual capture.
**Architecture:** Optional capture_note on the existing paired capture request and pending DTO; durable notes stay server-side and transfer transactionally to article_capture_notes. The native input has a local failure-retry draft, cleared only after durable acknowledgment.
**Tech stack:** Go/Gin/PostgreSQL RLS, React/Vitest, native Apple Shortcuts/plist.

- [x] Backend: add failing real PostgreSQL/API tests for note staging/listing, duplicate/blank append behavior, Unicode limits, owner isolation, note transfer from current server state, already-fetched child note, and commit-failure rollback. Add migration 061, persistence and API payload/acknowledgment. Preserve note-independent requests and return errors through request transaction rollback.
- [x] Reader: extend DraftLink and API DTO with optional capture_note; merge a remote note even when a local row already has the URL without persisting private server text in local scratchpad. Show note as escaped prewrapped text in the pending confirmation dialog, and do not send the cached note to batch confirmation. Test duplicate local/remote merge, live note refresh and actual dialog display; run all frontend tests/build.
- [ ] Native: add official Ask for Input with optional multiline text on every share after link/connection validation, safe retry draft isolation, JSON capture_note, and acknowledgment-aware clearing. Validate empty/nonempty/network-failed retry against a local fake API and fake credential path. Export and publish a credential-free official installer; update installer URLs only after verifying Apple archive.
- [ ] Root integration: wire ordered migration, test deployment selection and ensure only API/worker/frontend rollout for a migration-command-only compose change. Run two-stage independent review (spec then quality), integrate latest master, backend/full frontend/build/deploy checks, push actual master and deploy established Tencent target.
- [ ] Verify synthetic account on public deployed reader: note visible pending without child, explicit confirmation produces one child with private note and no parent/public note leakage, duplicate sharing appends idempotently, empty input retains existing note. Verify SHA/bundle/migration/RLS/service health, clean own fixtures, report precise native publication blocker if Apple prevents final export.

Implementation domains have exclusive file ownership: backend agent backend only; frontend agent reader/API types/tests only; native agent shortcuts/build script/install component/static setup/installer tests only. Root owns docs, compose and deployment tests. No worker process runs shared queued links automatically.

Validation so far: backend focused HTTP/repository and race suites passed; independent spec and quality reviews passed for backend, reader and scoped deployment. Integrated frontend: 803 tests passed and build succeeded. Native localhost fixture/isolation tests passed (3), but those are synthetic support artifacts only. Original published workflow still has 36 actions; optional native input, retry actions, native execution and Apple publication remain required until explicitly verified.

Staged release boundary: server persistence, reader display, scoped migrations and test support are ready. The published native shortcut still accepts URLs only; the capability flag stays false and the real Apple installer stays unchanged. Official editor permits constructing the new input, but both export modes report iCloud sign-in required. Read-only System Settings shows Apple Account not signed in; user sign-in was requested. No workaround for OS-denied source access is authorized. Full user delivery remains incomplete until native formats, pipeline execution and public installer are verified.
