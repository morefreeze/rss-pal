# 单篇文章外部分享设计

日期：2026-09-08

## 1. 目标

登录用户可以把一篇文章以不可变快照分享给游客：

- 每篇文章可以创建多个独立分享链接。
- 每个链接可以设置 7 天、30 天、自定义到期时间或永久有效。
- 每个链接可以单独复制和撤销。
- 游客无需登录即可阅读 AI 总结和完整正文。
- 分享后原文章更新，不改变已经生成的快照。
- 分享页提供“使用 RSS Pal”和“订阅原始来源”入口，两个入口均先进入登录或注册流程。

本功能不包括：

- 评论、点赞、收藏和访客阅读进度。
- 整个 RSS Pal 的游客模式。
- 永久保存所有远程图片和音视频文件。
- 修改现有的邀请码注册政策。
- 分享访问分析和访客画像。

## 2. 技术方案

采用“数据库快照 + 外部媒体引用”。创建分享时，把当时的文章展示数据保存到独立记录；远程图片、音频和视频只冻结 URL，不下载资源文件。

相比静态 HTML 或 CDN 导出，这种方式更容易即时撤销和管理；相比完整复制所有媒体，存储和版权风险更低。快照保证 RSS Pal 保存的文字、摘要和媒体地址不再变化，但不保证第三方地址对应的资源永久可用。

## 3. 数据模型

新增 `article_shares` 表：

- `id`：由应用生成的随机 UUID，同时作为公开 ID。
- `article_id`：原文章 ID；文章删除时级联删除分享记录。
- `created_by`：创建者用户 ID，不能为空。
- `snapshot_version`：快照结构版本，初始值为 `1`。
- `snapshot`：不可变的 JSONB 快照。
- `expires_at`：带时区时间；为空表示永久有效。
- `revoked_at`：带时区时间；为空表示未撤销。
- `legacy_token_digest`：旧链接 token 的 SHA-256 摘要；仅迁移记录使用，新链接为空。
- `created_at`：带时区创建时间。

建立 `(created_by, article_id, created_at DESC)` 索引，支持文章分享列表。数据库约束要求 `expires_at` 为空或晚于 `created_at`。
为非空的 `legacy_token_digest` 建立唯一部分索引。

快照包含：

- 标题、原文 URL 和来源名称。
- 发布时间、字数和预计阅读时间。
- 简短总结和详细总结。
- 完整正文。
- 图片尺寸信息。
- 公开媒体 URL、类型和时长。
- 快照生成时间。

快照明确排除：

- 用户名和用户 ID。
- 阅读进度、收藏状态、标签和兴趣信息。
- 编辑备注、推荐理由和处理错误。
- 原始 feed URL 和订阅凭据。

快照创建后，唯一允许变化的是 `revoked_at`；到期时间、正文及其他快照字段不允许原地更新。已撤销或已过期的分享不能重新激活。

## 4. 分享链接

分享链接格式为：

```text
/share/v1_<public-id>_<signature>
```

`signature` 使用独立的 `SHARE_SECRET` 对版本和公开 ID 做 HMAC-SHA256，再使用 URL-safe Base64 无填充编码。

服务端使用常量时间比较签名。数据库不保存可以直接访问分享页的完整 token；服务端可以根据公开 ID 重新计算链接，因此登录用户以后仍能复制已有链接。

安全和运维要求：

- 不复用 JWT 密钥。
- 生产环境没有 `SHARE_SECRET` 时服务启动失败。
- `SHARE_SECRET` 必须纳入安全备份。
- 直接轮换密钥会使现有链接失效；多密钥平滑轮换不属于本期范围。

## 5. 创建与管理流程

文章页的“分享”按钮打开分享弹窗。

创建区域提供：

- 7 天、30 天、自定义日期和永久四种有效期。
- 自定义时间必须晚于当前时间。
- “创建新链接”操作。
- 创建成功后自动复制链接。

当文章正文尚未抓取完成或正文为空时，不允许创建完整文章分享，接口返回可恢复的业务错误。

管理区域列出当前文章的全部分享：

- 创建时间。
- 到期时间或“永久”。
- 生效、已过期、已撤销或旧版状态。
- 复制链接操作。
- 撤销链接操作。

同一篇文章允许多个链接。撤销不可恢复；如需新的快照或重新分享，用户创建新链接。界面不提供编辑快照。

## 6. API 设计

### 6.1 登录接口

```text
POST   /api/articles/:id/shares
GET    /api/articles/:id/shares
DELETE /api/articles/:id/shares/:share_id
```

创建请求示例：

```json
{
  "expires_at": "2026-10-01T00:00:00Z"
}
```

永久分享传 `null`。

创建接口必须先通过受 RLS 约束的文章仓储查询确认当前用户可以访问该文章，再在同一事务中读取文章、生成快照并插入分享记录。接口不能仅根据客户端传入的 `article_id` 查询或写入未受 RLS 保护的分享表。

列表和撤销接口同时按 `created_by` 与 `article_id` 约束目标，不能操作其他用户的分享。撤销采用逻辑撤销，重复撤销保持幂等并返回当前状态。

### 6.2 公开接口

```text
GET /api/share/:token
GET /api/share/:token/assets/:asset
```

公开响应只返回快照展示字段，不返回内部 `article_id`、`feed_id` 或 `created_by`。资源接口仅服务 RSS Pal 本地保存的文章资源，并在每次请求时验证签名、到期时间、撤销状态和原文章存在性。

## 7. 游客页面

分享页采用精简阅读器，不加载登录用户的主导航和私有数据请求。

页面展示顺序：

1. RSS Pal 和“分享文章”标识。
2. 标题、来源、发布时间和阅读时长。
3. AI 简短总结和详细总结。
4. 完整正文。
5. 可用的音频或视频。
6. 阅读原文入口。
7. “使用 RSS Pal”和“订阅原始来源”入口。

实现时复用当前 Markdown、代码、公式、图片和视频的纯展示能力，但不能直接复用包含登录用户交互的完整 `ArticlePage`。应把纯展示渲染与右键菜单、链接选择、阅读进度等私有交互分离，确保游客页面不触发任何私有写接口。

## 8. 登录与订阅承接

“使用 RSS Pal”流程：

```text
分享页 -> /login -> 登录或注册 -> /articles
```

“订阅原始来源”流程：

```text
分享页
  -> /login?intent=subscribe&source=<原文 URL>
  -> 登录或注册
  -> 添加订阅页面
  -> 根据原文章网页重新发现 RSS
```

约束：

- `next` 参数只能接受站内路径，避免开放重定向。
- `intent` 使用固定白名单。
- 从登录页切换到注册页时保留 intent 和安全校验后的来源信息。
- 当前注册仍需要邀请码；本功能不自动开放公开注册。
- 不把分享者实际保存的 feed URL 传给游客，以免泄露私有 token。
- 自动发现失败时进入手动添加流程，不自动创建错误订阅。
- 登录或注册失败后，访客仍能返回原分享页继续阅读。

## 9. 图片和音视频

- 远程图片继续通过现有 SSRF 防护图片代理加载。
- 快照保存原始图片 URL 和图片尺寸，但不保证第三方资源永久可用。
- RSS Pal 本地保存的 PDF 图片改用分享专属资源地址，每次读取都检查分享是否有效。
- 撤销、过期或删除原文章后，本地资源接口立即拒绝访问。
- YouTube 等公开嵌入继续展示。
- 依赖用户 Cookie、私有订阅凭据或内部播放中继的媒体，降级为“前往原网站播放”。
- 单个图片或媒体失败不能导致整页加载失败。

## 10. 安全与缓存

- 修复现有创建接口缺少文章所有权验证的问题。
- 不再创建 8 位 `math/rand` token。
- 无效、伪造、过期、撤销和已删除的链接，对游客统一显示“分享链接无效或已过期”。
- 分享页面设置 `Referrer-Policy: no-referrer`，避免访问原文时泄露分享 URL。
- 分享 API 使用 `Cache-Control: no-store` 或足够短的缓存时间，保证撤销快速生效。
- Markdown 链接和媒体协议使用白名单。
- 公开接口按 IP 实施有限速率限制，并只信任由明确配置的反向代理写入的来源头。
- 日志只记录公开 ID，不记录完整分享 URL、签名或正文。
- 不添加离线缓存和 Service Worker 缓存。
- 已经下载、复制或截图的内容无法因撤销而追回，界面应明确这一限制。

## 11. 错误处理

登录接口：

- 文章不存在或无权限返回 404。
- 正文尚未完成或为空返回 409。
- 到期时间无效返回 400。
- 数据库或快照创建失败时回滚整个事务，不产生半成品链接。
- 重复撤销返回成功及当前状态。

游客接口：

- 所有无效分享状态使用统一的 404 API 响应和统一页面文案，不区分不存在、签名错误、过期、撤销或原文章已删除。
- 页面级请求失败提供重试入口。
- 单个资源失败显示占位，不影响正文。
- CTA 登录失败后仍保留返回原分享页的路径。

## 12. 旧链接兼容

采用部署后 30 天的有限兼容期：

- 部署迁移时，为现有 `share_tokens` 对应文章生成一次版本 1 快照。
- 迁移只把旧 token 的 SHA-256 摘要写入 `legacy_token_digest`，不把旧 token 明文复制到新表；旧请求通过摘要查询兼容记录。
- 旧 8 位链接继续工作 30 天。
- 旧链接在管理弹窗中标记为“旧版链接”，允许立即撤销，但不允许复制、延长或恢复。
- 界面引导用户创建新版链接。
- 兼容期结束后旧链接统一失效，并移除旧读取逻辑。
- 旧接口在新版本部署后立即停止创建旧格式 token。
- 完成迁移校验后删除旧 `share_tokens` 表，避免继续保存旧 token 明文。

迁移生成的快照代表部署迁移时的文章状态，而不是旧链接最初创建时的状态；界面和迁移说明需明确这一限制。

## 13. 测试边界

后端测试覆盖：

- 跨用户不能创建、列举或撤销对方的分享。
- 同一文章可以创建多个链接。
- HMAC 正确、篡改、截断和错误版本。
- 永久、未来到期和已经到期状态。
- 撤销幂等。
- 更新原文章后快照保持不变。
- 删除文章后分享失效。
- 快照不包含私有字段。
- 分享资源接口遵守过期和撤销状态。
- 旧链接及 30 天兼容边界。

前端测试覆盖：

- 创建不同有效期的链接。
- 分享列表、复制、撤销和状态变化。
- 游客完整正文渲染。
- 游客页面不触发进度、收藏等私有 API。
- 图片和媒体降级。
- 两个 CTA 的登录、注册及返回路径。
- 无效、过期和撤销页面。

交付前执行完整后端测试、前端测试、前端生产构建及变更范围检查。

## 14. 验收标准

- 无痕浏览器可以打开分享链接并阅读完整文章。
- 同一文章的两个分享链接互不影响。
- 修改原文章后，已有快照内容不变。
- 撤销一个链接后，该链接及其本地资源不可访问，其他链接正常。
- 到期时间按服务端 UTC 时间准确生效。
- 页面和网络响应中没有用户私有数据或原始 feed URL。
- 登录后能从两个 CTA 到达正确目的地。
- 现有登录用户阅读功能不发生回归。
