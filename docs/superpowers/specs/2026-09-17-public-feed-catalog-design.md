# 管理员公共推荐目录

## 已确认目标

提供独立于个人订阅的人工精选公共目录。管理员维护目录，用户主动订阅后获得自己独立的订阅；管理员个人订阅的共享、暂停、删除均不能改变目录。探索自动发现的候选池保持独立。

## 页面与操作

- 管理员桌面与移动端导航增加「公共推荐目录」，路由 `/admin/feed-catalog`。
- 管理页展示标题、RSS 地址、分类、简介、排序、草稿/已上架状态、最近检查时间与检查结果，支持新增、编辑、检查、上架和下架。
- 列表支持按标题或地址搜索、按发布状态筛选。排序数值越小越靠前，同值按 ID 排序。
- 使用下架保留条目；第一期不提供永久删除、批量导入、自动将个人订阅加入目录或自动将探索候选发布到目录。
- 普通用户订阅页的「热门推荐」改为读取服务端目录，沿用预览并确认订阅流程。新用户仍为零订阅。

## 数据与接口边界

- 新建 `public_feed_catalog`，不复用个人 `feeds`，也不把探索 `recommended_feeds` 当作人工发布目录。
- 保存标题、RSS URL、规范化去重键、分类、简介、排序、发布状态、最近检查时间/结果/错误、创建和更新管理员及时间。
- 已登录用户可读取已上架条目；草稿、管理字段及管理操作仅管理员可访问。后端从数据库确认管理员身份，不能只依赖前端隐藏入口。
- 目录操作不创建、修改或删除任何用户的订阅、文章、阅读状态。用户订阅继续使用现有按当前用户隔离的创建接口与配额。
- URL 去重与字段长度在服务端校验。管理写入只接受白名单字段，发布采用明确目标状态，避免重复请求反转状态。

## 验证与上架

- 新条目默认草稿。上架必须对当前 URL 完成一次成功的 RSS 检查；编辑 URL 后撤销旧检查结果并退回草稿。
- 检查与上架使用现有具备 DNS、重定向和内网地址防护的抓取路径；RSSHub 来源仅通过现有可信平台转换规则，不允许任意内网地址。
- 一次检查有超时、并发和现有交互抓取额度限制，不启动个人订阅抓取或 AI 摘要。
- 检查记录与被检查 URL 绑定；检查过程中发生编辑时，旧结果不能使新 URL 上架。重复上架和下架应安全。
- 网络错误可重试并向管理员显示可读原因；失败不能造成条目首次上架。已上架条目的手动复查失败显示异常，不静默删除用户订阅。
- 本期目录检查表示源可解析；探索页最近 12 小时抓取规则继续独立执行，不将目录检查时间冒充探索文章刷新时间。

## 历史迁移

- 将当前前端 `POPULAR_FEEDS` 全部迁移为独立目录条目，保留分类、标题、简介与展示顺序；迁移幂等，不扫描或公开个人订阅。
- 迁入条目先为草稿并通过真实检查后上架，不伪造验证成功时间；检查失败的条目留在管理页显示原因。
- 对现有 RSSHub 内部地址使用与受支持平台对应的可安全输入形式，不能通过给任意内部 URL 放行来保留旧名单。
- 移除前端硬编码推荐数据；服务端读取失败显示加载错误与重试，不退回过期名单。

## 验收与交付

1. 未登录不可管理，普通用户不可读草稿、不可增改或上架。
2. 草稿不出现在热门推荐；验证后上架可见，下架后消失。
3. 管理员个人订阅增删暂停不影响目录；两个用户订阅同目录源后状态独立。
4. 无效 RSS、私网地址、重定向到私网、重复 URL、并发编辑检查均不能绕过发布要求。
5. 桌面和移动端管理员能找到入口，普通用户看不到管理入口；目录操作反馈明确。
6. 在独立工作区完成后端与前端相关验证，推送 master 并部署腾讯；核对部署提交、运行服务、健康与实际页面。保留另一任务未提交文件。
