# 热门推荐三天后自动折叠 — 设计

**日期：** 2026-07-16  
**范围：** 仅订阅页前端  
**目标文件：** `frontend/src/pages/FeedListPage.tsx`

## 问题

订阅页的「热门推荐」当前默认长期展开。它包含 7 个分类、28 个推荐源，用户熟悉这一区域后仍会持续占据较多页面空间。

## 目标

以当前浏览器首次展示「热门推荐」的时间为起点：

- 前 72 小时保持整个模块默认展开。
- 满 72 小时后，整个模块默认折叠为一行标题。
- 用户始终可以点击标题手动展开或折叠。
- 展开模块后，现有 7 个分类各自的折叠交互保持不变。

## 方案

### 时间记录

使用 `localStorage` 保存首次展示时间，键名为：

```text
rsspal:popular-feeds:first-seen-at
```

值为 `Date.now()` 产生的毫秒时间戳。三天阈值固定为：

```ts
3 * 24 * 60 * 60 * 1000
```

不新增 API、数据库字段或账号级同步。不同浏览器和设备各自计时。

### 初始状态

`FeedListPage` 首次渲染时通过惰性 state initializer 计算模块初始状态：

1. 键不存在：写入当前时间，返回展开。
2. 时间戳有效且未满 72 小时：返回展开。
3. 时间戳有效且已满 72 小时：返回折叠。
4. 值无法解析、不是有限正数或晚于当前时间：用当前时间覆盖并返回展开。
5. `localStorage` 不可用或抛错：不写入，安全降级为展开。

手动展开/折叠只影响当前页面生命周期，不覆盖首次展示时间：未满三天时刷新后仍默认展开，满三天后刷新仍默认折叠。

### 页面交互

将现有静态「热门推荐：」标签改为可点击的模块标题按钮：

- 展开显示 `▾`，下方渲染全部分类。
- 折叠显示 `▸`，不渲染分类列表和推荐 chips。
- 保留现有 `foldedGroups` 状态和分类按钮，不改变推荐源内容、Preview 行为或添加订阅流程。

## 错误与兼容处理

- 读取或写入存储失败不影响订阅页渲染。
- 不依赖系统定时器持续更新；72 小时判断发生在页面加载时，避免常驻 timer。
- 采用毫秒时间戳，不受时区和夏令时变化影响。
- 不清理现有分类折叠状态，因为它当前仅存在于 React state。

## 验证

### 构建检查

```bash
cd frontend
npm run build
```

### 行为检查

1. 清除存储键并打开订阅页：模块展开，键被写入。
2. 将键设为 71 小时前：模块展开。
3. 将键设为 73 小时前：模块折叠成一行。
4. 在自动折叠状态点击标题：分类和 chips 出现；再次点击后隐藏。
5. 写入非法值或未来时间：模块展开并重新记录当前时间。
6. 展开模块后，分类级展开/折叠和点击推荐源 Preview 均保持正常。

## 非目标

- 不跨设备同步首次展示时间。
- 不新增关闭、永久隐藏或重置推荐的设置。
- 不调整推荐源列表、分类或排序。
- 不修改后端、数据库、Worker 或 RSSHub。

## 验收标准

- 新用户首次看到热门推荐时默认展开。
- 同一浏览器首次展示满 72 小时后，热门推荐默认折叠为一行。
- 用户可随时手动展开/折叠，现有分类折叠功能不回归。
- 存储异常不会阻断订阅页。
- 前端生产构建通过。
