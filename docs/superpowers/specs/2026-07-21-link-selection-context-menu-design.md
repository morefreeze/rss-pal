# 链接选区上下文菜单与隐式 link_set

**日期：** 2026-07-21
**状态：** 已批准实施
**范围：** 阅读器链接选择、待抓取草稿、批量抓取启用流程、文章详情缓存一致性

## 背景

当前 link_set 交互要求用户先点击“💡 转为 link_set”，再通过正文链接尾部的邮箱图标逐个标记。这个流程有两个问题：

1. 转换请求实际上已经写入 `links_extendable=true`，但前端紧接着重新获取文章详情时可能仍拿到旧响应，因此按钮看起来没有反应，刷新后才生效。
2. 每个链接后常驻图标既打断阅读，也把“选择链接”过早绑定为 link_set 专属交互，无法自然扩展到后续划线、评价和名词补充等阅读器动作。

第一个问题的根因是文章详情 ETag 只覆盖正文、摘要和 `processing_state`，没有覆盖 `links_extendable`、`link_set_suggested`、children 及其他详情响应状态。转换后的详情与转换前得到相同 ETag，浏览器可以复用旧响应。

## 目标

- 删除显式“转为 link_set”步骤，任何文章中的 HTTP(S) 链接都能加入待抓取集合。
- 桌面端通过文本选择触发菜单，不接管浏览器右键菜单。
- 移动端通过长按链接触发同一套动作菜单。
- 用户只选中链接文字的一部分时，也把整个链接识别为动作目标并完整高亮。
- 移除正文链接尾部常驻图标，以轻量样式反馈已加入状态。
- 建立可复用的阅读器上下文菜单层，后续能追加划线、评价和名词补充动作。
- 首次批量提交时原子地启用 link_set 并创建 children。
- 修复文章详情 ETag，使成功写入后的立即重取和 children 轮询不会复用旧 UI 状态。

## 非目标

- 本次不实现纯文本划线、评价或名词补充。
- 本次不为普通纯文本选区显示空菜单或不可用的未来入口。
- 不删除 worker 的 link-set 候选检测、候选缓存或既有候选 API。
- 不改变 worker 抓取、摘要和推荐排序流程。
- 不把未提交的待抓取草稿写入数据库或跨设备同步。
- 不接管桌面浏览器的原生右键菜单。

## 已确认的产品规则

- 所有正文 HTTP(S) 链接都可加入，不限于 worker 识别出的候选链接。
- 桌面端在完成文本选择后检查选区；只有选区覆盖至少一个链接时才显示自定义菜单。
- 桌面端右键始终保留浏览器原生菜单，鼠标触发的 `contextmenu` 不得调用 `preventDefault()`。只有一次已成功识别的移动端长按可以抑制其紧随产生的原生 `contextmenu`。
- 移动端长按链接约 500ms 打开自定义菜单；移动或滚动取消长按。
- 选区与链接文字有任意非空文本重叠时，该链接整体成为目标。内部目标范围和临时高亮都扩展到完整 `<a>`，而不是仅使用被选中的几个字符。
- 多链接选区把每个相交链接作为完整目标，按正文顺序排列并按标准化 URL 去重。
- 已加入链接使用蓝色虚线下划线；不再显示邮箱图标。
- 待抓取集合非空时显示 `📥 待抓取 N`，为空时不显示按钮。
- 首次确认抓取自动启用 link_set；不再显示“💡 转为 link_set”。

## 方案比较

### 方案 A：继续扩展 `LinkSetContext`

把邮箱按钮替换为选区监听和菜单，但所有接口仍以 link_set 命名。

优点是改动小。缺点是选区定位、菜单、长按、键盘和关闭行为都会与 link_set 状态耦合，后续做阅读标注时还要再次拆分。

### 方案 B：通用 `ReaderContextMenu`（采用）

阅读器只产出上下文目标，菜单层根据目标和已注册动作渲染。link_set 提供第一组动作；后续标注功能可复用定位、关闭、焦点和动作执行机制。

优点是边界清晰，可同时用于普通文章模式和沉浸阅读模式，并为后续标注留下稳定接口。代价是本次需要提取一个小型通用层。

### 方案 C：文章根节点全局 DOM 事件代理

在 `document` 或文章根节点统一查询 Selection 和链接 DOM，不让 Markdown 组件感知交互。

代码入口少，但依赖 DOM 结构和全局监听，文章切换、多个阅读器实例、无障碍焦点及组件测试都更脆弱，因此不采用。

## 架构

### 通用目标与动作

新增阅读器上下文菜单组件和目标类型。目标只描述“用户作用于什么”，不包含 link_set 业务状态：

```ts
type ReaderLinkTarget = {
  url: string
  title: string
  element: HTMLAnchorElement
}

type ReaderContextTarget =
  | {
      kind: 'selection-links'
      links: ReaderLinkTarget[]
      anchorRect: DOMRect
    }
  | {
      kind: 'long-press-link'
      links: [ReaderLinkTarget]
      anchorRect: DOMRect
    }

type ReaderContextAction = {
  id: string
  label: string
  disabled?: boolean
  run: () => void | Promise<void>
}
```

`ReaderContextMenu` 接收目标和动作数组，负责：

- 菜单定位与视口边界修正；
- 点击外部、Escape、滚动、文章切换时关闭；
- 打开时把焦点移到第一个可用动作；
- 上下方向键移动焦点，Enter/Space 执行；
- 关闭后把焦点还给触发链接或文章根节点；
- 执行中的禁用和错误反馈容器。

菜单打开时保存不可变的目标快照。菜单自身的 `pointerdown` 不得因浏览器折叠 Selection 而提前销毁动作目标；动作完成、显式关闭或文章选区真正改变后再清理快照和临时高亮。

link_set 适配器根据当前待抓取集合、已抓取 children 和目标链接生成动作。未来标注功能可以为文本选区生成其他动作，但不需要重写菜单定位与生命周期。

### 组件边界

- `MarkdownArticle`：暴露文章正文根节点，给已加入链接附加样式类，并接入桌面选区与移动端长按识别。
- 阅读器交互层：把 DOM Selection 或长按事件转换为 `ReaderContextTarget`，管理完整目标高亮。
- `ReaderContextMenu`：只渲染通用菜单和执行动作。
- `ArticlePage`：拥有当前文章的待抓取草稿、children 状态和确认对话框状态。
- `ReadingLayout`：接收与普通模式相同的阅读器动作配置，避免沉浸模式另造状态。
- `BatchFetchConfirmDialog`：只消费待抓取草稿，不再依赖 worker 候选列表。

## 桌面选区行为

### 触发

在文章正文根节点监听 `pointerup`、键盘选择完成后的 `keyup`，并用 `selectionchange` 处理 Selection 的异步变化。一次稳定的非折叠 Selection 必须完全位于当前文章正文内。

从 Selection Range 查找所有与选区存在非空文本重叠的 `<a href>`：

- 选中一个链接的任意部分，目标扩展为整个链接；
- 选区从普通文本跨入链接，目标仍是整个链接；
- 选区跨越多个链接，每个相交链接都整体成为目标；
- 仅在边界处接触链接、但没有选中任何链接字符时，不计入；
- 纯文本选区、图片、代码块或文章正文之外的选区不弹菜单。

目标链接在菜单打开期间统一增加临时高亮类，使用户看到完整动作范围。这个高亮不修改文章 Markdown，也不把临时状态写入草稿。菜单关闭或选区变化时移除。

若拖选结束产生浏览器 `click`，并且该点击位于当前非折叠选区覆盖的链接内，阅读器阻止这一次导航，避免用户在选择链接文字时意外打开页面。普通单击链接行为不变。

### 菜单动作

桌面选区菜单只显示与批量选择相关的动作：

- 存在未加入链接时：`加入待抓取（N）`；
- 存在已加入链接时：`移出待抓取（N）`；
- 同一选区混合两种状态时，同时显示两项；
- 已抓取链接显示只读状态，不计入可加入数量。

打开、复制等标准链接动作继续由原生右键菜单承担。

## 移动端长按行为

移动端在链接上按下后启动 500ms 定时器：

- 到达阈值且移动距离未超过 8px时打开菜单；
- `pointermove` 超过阈值、滚动、`pointercancel` 或提前松手时取消；
- 成功触发长按后抑制紧随其后的单击导航；
- 成功触发长按后只抑制这一次触摸产生的原生 `contextmenu`，不得影响桌面鼠标右键；
- 普通短按仍按浏览器默认行为打开链接。

移动端菜单针对单个链接显示：

- `加入待抓取` 或 `移出待抓取`；
- `在新标签页打开`；
- `复制链接`；
- 已抓取时显示 `已抓取`，不允许重复加入。

由于移动端长按被应用接管，打开与复制必须保留，避免丢失系统菜单的核心能力。剪贴板 API 不可用时显示明确错误，不静默失败。

## URL 识别与标准化

只有解析后 scheme 为 `http:` 或 `https:` 的链接可成为待抓取目标。相对链接以文章 URL 为 base 解析。

前后端沿用同一 link-set URL 标准化语义：

- host 小写；
- 移除 fragment；
- 去除 `utm_*`、`ref`、`mc_cid`、`mc_eid`、`fbclid`、`gclid`；
- 对剩余 query key 排序；
- 移除非根路径末尾斜杠。

选区内重复出现的标准化 URL 只产生一个草稿项，以第一次出现的位置和链接文字为准。

## 待抓取草稿

### 数据结构

待抓取状态从 `Set<string>` 升级为有序记录：

```ts
type DraftLink = {
  url: string
  title: string
  addedAt: number
}
```

`title` 使用去除多余空白后的完整链接可见文字；为空时回退到 hostname，再回退到 URL。手动选区加入不生成 `editor_note`。

### 持久化

继续使用每文章 localStorage key 和 24 小时 TTL，但 envelope 增加 `version: 2`。读取时兼容旧 `{ urls, savedAt }`：

- 旧 URL 仍存在于正文时，从当前链接文字补齐 title；
- 正文中找不到时以 hostname 或 URL 作为 title；
- 非法或非 HTTP(S) URL 丢弃；
- 迁移后的下一次写入使用 v2 格式。

localStorage 不可用、超限或数据损坏时退化为当前页面内存状态，不阻止阅读和抓取。

### 正文反馈

草稿中的链接使用蓝色虚线下划线和轻微蓝色底色，不增加尾部图标。菜单打开期间的“完整目标高亮”比草稿样式更明显，但关闭菜单后只保留草稿样式。

待抓取集合非空时显示 `📥 待抓取 N`；集合为空时不渲染按钮。普通模式和沉浸阅读模式共享数量与草稿。

## 确认与提交

`BatchFetchConfirmDialog` 直接接收 `DraftLink[]`，按加入顺序显示。对话框继续支持：

- 本次全选、反选、取消全选；
- 单行取消本次提交；
- 从草稿彻底移除；
- 已抓取状态禁用；
- 提交中防止重复请求。

请求成功后仅移除本次实际提交的 URL；未勾选项继续保留。服务端以成功响应接纳整批请求，即使某些 URL 因唯一约束已存在、`inserted` 小于提交数量，这些已提交项也从草稿移除。

请求失败时保留草稿、勾选状态和对话框，展示服务端错误。

## 隐式启用 link_set

前端删除：

- `💡 转为 link_set` FAB；
- `confirmLinkSetSuggestion` 调用；
- 正文 `LinkSetMarkIcon` 邮箱按钮；
- `links_extendable` 对待抓取入口的状态门；
- 对候选 API 返回值的确认对话框依赖。

`POST /api/articles/:id/batch_fetch` 在完成整批验证后，在当前 RLS 请求事务内：

1. 验证父文章对当前用户可见；
2. 标准化并去重请求 URL；
3. 设置父文章 `links_extendable=true`；
4. 插入 children；
5. 返回 `inserted`。

任一步骤失败都使请求返回错误并由外层事务整体回滚。首次提交和后续提交走相同路径，因此无需前端判断是否已经启用。

后端 `confirm_link_set` 路由暂时保留，供旧客户端兼容；新前端不再调用。worker 的 `link_set_suggested`、候选检测和 `link_set_candidates` 表保留，但不再决定手动选择入口是否可见。

文章页以 `links_extendable === true` 或非空 children 决定是否渲染 `LinkSetChildren`，不再读取前端 `Article` 类型中没有可靠后端来源的 `is_link_set`。

## 批量请求校验

服务端在任何写入前校验完整请求：

- 每批最多 100 个链接；
- URL 必须是绝对 HTTP(S) URL，最长 4096 字符；
- title 去除首尾空白，最长 500 字符，空值回退到 URL；
- `editor_note` 最长 2000 字符；
- 标准化后按 URL 去重；
- 去重后为空返回 400。

非 HTTP(S) scheme、无 host、解析失败或超限项使整批返回 400，不做部分接受。worker 获取内容时继续使用既有网络安全与抓取限制。

## 详情 ETag 一致性修复

当前 `ComputeDetailETag(model.Article)` 在读取 progress、signals、hidden 和 children 之前运行，且哈希不包含 link-set 标志。这违反了 HTTP validator 必须代表完整响应的要求。

新的详情流程为：

1. 读取 article、progress、signals、hidden，以及启用后的 children；
2. 组装完整详情响应；
3. 对将要发送的稳定 JSON 表示计算私有 ETag；
4. 仅当 `If-None-Match` 与完整表示一致时返回 304；
5. 200 响应复用同一份序列化结果，避免“哈希内容”和“实际响应”不同。

因此以下变化都会生成新 ETag：

- `links_extendable` 或 `link_set_suggested`；
- children 新增、处理状态、错误或内容变化；
- progress、signals、hidden；
- 正文、摘要及文章其他详情字段。

列表接口的 ETag 逻辑不在本次范围内。

## 错误处理与并发

- 菜单动作执行期间禁用对应按钮，避免双击重复写入草稿。
- Selection 在菜单打开前失效时丢弃本次目标，不使用陈旧 DOM 节点。
- 文章切换时关闭菜单并切换到新文章的草稿 key。
- 同一 URL 多处出现时共享草稿状态，任意一处加入或移出都会同步更新所有实例样式。
- 已抓取状态优先于草稿状态；刷新发现 URL 已成为 child 时从草稿中清理。
- `batch_fetch` 依赖数据库唯一约束处理并发重复提交；重复项不报错。
- 首次提交插入失败时 `links_extendable` 不得单独提交。
- 详情刷新失败时保留已提交成功提示和现有 children，提供手动重试，不把已提交 URL重新放回草稿。

## 无障碍与视觉规则

- 菜单使用 `role="menu"`，动作使用 `role="menuitem"`。
- Escape 关闭；方向键移动；Enter/Space 执行；Tab 关闭并回到正常页面焦点顺序。
- 临时完整目标高亮和已加入样式不能只依赖颜色：前者使用背景与轮廓，后者使用蓝色虚线下划线。
- 已加入链接保留原链接语义、href 和键盘激活行为。
- 菜单不能遮住整个选择范围，并必须在窄视口内翻转或收缩。
- `prefers-reduced-motion` 下不使用位移动画。

## 测试设计

### 前端单元与组件测试

- 选中链接中间几个字符时，提取完整 anchor URL/title，并给整个 anchor 添加临时高亮。
- 选区从普通文本进入链接、从链接进入普通文本、跨越多个链接时，完整目标集合正确。
- 仅边界接触不计入；纯文本、代码块、图片和正文外选区不弹菜单。
- 相对 URL、tracking 参数、fragment、尾斜杠和重复 URL 正确标准化与去重。
- 鼠标 `contextmenu` 不被阻止，桌面原生右键保持不变；成功的移动端长按只抑制对应的一次触摸 `contextmenu`。
- 菜单获得焦点或按钮收到 `pointerdown` 时仍使用打开时的目标快照，不因 Selection 折叠而丢失动作。
- 拖选链接文字后的合成 click 不导航，普通 click 正常导航。
- 移动端 fake timer 覆盖 500ms 成功、8px 移动、滚动、取消和短按。
- 混合选区正确显示加入/移出数量；已抓取项不可加入。
- v1 localStorage 迁移、v2 恢复、24 小时过期、损坏数据和存储异常。
- 蓝色虚线、临时高亮、FAB 数量和同 URL 多实例状态同步。
- 对话框成功只清除提交项，失败保留草稿与勾选状态。
- `ArticlePage` 和 `ReadingLayout` 都使用同一阅读器动作配置。

### 后端测试

- 任意合法 HTTP(S) 链接可提交，不要求存在候选缓存。
- 非 HTTP(S)、无 host、非法 URL、超长字段、空请求和超过 100 条整批返回 400。
- 标准化 URL 在请求内去重，数据库唯一约束处理并发重复。
- 第一次提交同时写入 `links_extendable=true` 和 children。
- child 插入失败时确认 `links_extendable` 回滚。
- RLS 下不能对不可见父文章创建 children。
- 详情 ETag 会随 link-set flags、children 状态、progress、signals 和 hidden 变化。
- 相同完整详情响应仍返回稳定 ETag，并正确命中 304。

## 人工验收

1. 不再出现“💡 转为 link_set”和链接尾部邮箱图标。
2. 桌面只选中链接的一部分时，整条链接临时高亮并出现菜单。
3. 跨多个链接选择时，每条链接完整高亮，菜单数量正确。
4. 纯文本选择不弹菜单，右键仍显示浏览器原生菜单。
5. 移动端短按正常打开，长按弹菜单，滑动不误触。
6. 加入后显示蓝色虚线下划线与 `待抓取 N`，刷新后草稿恢复。
7. 首次确认无需预先转换，提交后 children 立即出现。
8. children 从 processing 变为 ready/failed 时，无需强制刷新即可看到新状态。
9. 提交失败不丢草稿；部分勾选成功后未提交项仍在。
10. 普通模式和沉浸阅读模式行为与数量一致。
