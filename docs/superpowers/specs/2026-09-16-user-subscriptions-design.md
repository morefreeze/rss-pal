# 用户订阅独立设计

用户确认：新用户初始 0 个订阅，推荐源仅供选择，点击订阅后才加入个人列表。

采用现有 owner-scoped feeds 作为个人订阅记录，recommended_feeds / explore 缓存继续承担公共目录与预览；不引入第二套成员关系表。订阅同一 URL 的两人拥有不同 feed ID，状态、标题、权重、归档与删除互不影响。探索缓存可以复制到个人订阅，禁止复用 owner_id=NULL 的全局 feeds 行。相较新增公共 feed membership，此方案复用已有实现和唯一索引，避免两套订阅真相；抓取仍按个人归属受现有额度约束。

迁移历史 NULL-owner feeds 到管理员 ID1，保留 feed/article ID、状态、文章及关联记录；遇到同 owner/url 冲突失败停止，不能自动合并/删数据。没有管理员时仅空库允许通过；有遗留共享源但没有管理员时拒绝迁移。不为普通用户自动创建5个订阅。历史个人行为记录不删除。

正式订阅列表、个人文章流、统计及 RLS 以 owner 为边界。公共推荐和已授权分享快照仍可访问。新增/导入/探索订阅均按当前用户创建，不能把别人的订阅当作已经订阅。

前端说明“推荐公开、我的订阅和状态仅自己可见”；空列表提供推荐入口。保留管理员原来的2个暂停状态，新用户自主订阅默认active。

验证：A/B同URL不同ID、暂停/权重/删除互不影响，新用户0订阅/0个人文章但能看推荐；迁移保留管理员ID和文章、可重跑；完整后端前端和腾讯部署验证。
