# 探索源关联与新鲜度

目录条目的 `provider_id + external_key` 在 RSS 地址规范化后仍代表同一条目录记录。再次同步时复用唯一已验证的规范源，保留其真实 RSS 地址；304 只刷新最新目录版本仍包含的 external_key 对应的观察记录，不能复活已移除条目。

推荐生成、冷启动列表和已有推荐列表均要求源最近 12 小时成功抓取且时间不在未来。目录观察时间不能代替抓取成功时间，也不能靠修改时间戳使旧缓存达标。该窗口覆盖正常 3 小时调度和夜间间隔。

定时调度先安排有效源刷新，其队列优先级为 800；普通验证和失败退避保持原规则。抓取成功后生成的推荐最多包含 12 个源，每源最多展示 5 篇文章。

管理员恢复命令（服务器、使用现有 Worker 配置）：

```
docker compose run --rm --no-deps worker ./worker --refresh-explore-once
```

此命令只执行一批最多 60 个探索任务，然后生成新的推荐批次；不启动个人订阅、AI 或其他循环。原有探索并发上限仍生效。操作前应避免同时执行另一个恢复命令，运行后核对推荐批次及真实 `last_fetched_at`。

历史重复关联可从同 provider、同 external_key、当前目录版本实际存在的记录恢复观察时间，不能使用当前时间批量覆盖所有源。普通 304 同步也会完成这项修复。无需删除公共文章缓存或用户订阅。
